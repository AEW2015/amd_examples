Timing & evidence boundaries

Host RTT measures UDP send to receive. Host encryption before sending and host verification after receiving are outside RTT. Device processing comes from a following stats probe, aligned to the preceding request: it includes copies, crypto and response assembly, rather than isolated AES/SHA latency. The stats probe adds traffic outside the primary RTT. Observed payload rate counts input bytes per elapsed wall time; it is not wire bandwidth or saturation throughput.

All successful operations compare the returned payload or digest against the host result. AES-GCM replies additionally verify their tags. Negative-test error replies are unauthenticated diagnostics. JTAG only loads the image; it does not carry measured payloads. Maximum-throughput mode uses one request in flight in verified 64-packet batches, with one device-timing probe after each batch. Presentation mode limits traffic to 20 requests/s. Input data is reused within each batch; every encrypted request and response still uses a fresh nonce. RTT includes pipeline queueing. The link meter shows input payload rate as a fraction of 100 Mb/s, excluding wire overhead; full-duplex directions are not added together.

Architecture, post-quantum scope & build status

AMD catalog IP throughout the IPI design. 2,952 LUTs · 36/48 BRAM tiles · routed WNS +3.867 ns. Four reviewed CDC-11 critical warnings remain unwaived; this is a functional lab build, not a production-qualified network security product.

HSS/LMS post-quantum signature verification and signed-PDI boot are separate demos. They cannot be selected as an Ethernet data-encryption mode in this firmware. SHA3/SHAKE are building blocks used in hash-based signatures; selecting a hash alone does not create post-quantum authenticated boot. PUF registration, key-source changes and secure boot are not controlled by these live buttons.
